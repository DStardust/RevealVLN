## 2. 一套基础设施、两个分开的生产分支

```text
合法资产 + R2R-CE train
        ↓ 来源哈希 / 房屋分组 / 历史暴露登记
        ├─ 普通导航：原指令与参考路线 → 动作编译 → 真实回放 → RGB/动作/STOP
        └─ 机制数据：历史候选 → 真实汇合 → 交叉续接 → 事件证书 → Y 与恢复动作
        ↓ 分支各自验收、失败账本、去重与配额
策略输入白名单文件  +  单独的离线监督文件  +  不可变 shard 索引
```

### 普通导航分支

1. 使用原始自然语言，不通过自由润色制造新的“精确语义标签”。
2. 以完整 reference_path 为路线约束编译合法动作，不只对终点跑最短路；否则可能绕过指令中的路标。
3. 在真实模拟器中从声明起点执行并保存每步 RGB、已执行动作、下一动作与 STOP；路点不直接冒充动作。
4. 保持现有原语 F=0.25m、L/R=15°，首版 RGB 224×224、HFOV90°；相机、碰撞体与动作参数写入配置哈希。
5. 正式 pilot 运行前锁定路线跟踪误差、动作上限、终点/STOP 验收和失败规则；记录参考路线一致性，而非仅到终点。不得把程序检查通过称为逐句自然语言语义全已证明。
6. 同一物理轨迹对应多条原指令时共享内容寻址 RGB；指令配对保留，但独立规模按路线和房屋计数。
7. 这一路可以在独立的普通回放验收后生产，不以机制族成功为前提；它的可用性不签发机制科学 PASS。

### 机制数据分支

1. 先以版本化 G1R 修正起点覆盖：先覆盖 32 个起点，再扩展 yaw/tail；不降低 SEE2、物理汇合或标签要求。
2. 取得首个合法候选即冻结；按原协议完成 27 次物理重放、54 次任务求值、一致性和完整 schema 验收。
3. 首个族通过后才编写跨房屋任务实例化协议。当前固定餐椅/水槽/床/电视族是验收夹具，不是直接复制到所有房屋的完整数据集。
4. 后续任务实例化只能由可观察的、机器可验证的类别/关系/时序语法生成；语言必须忠实对应谓词。当前 SEE2 不改叫“进入房间”或“到达床边”。
5. `Y[history,task,continuation]` 来自完整真实执行日志；合法任务失败可为负例，缺证据保持 unknown，碰撞/非法轨迹直接 rejected。
6. 通过的 normal/recovery continuation 才输出规定位置的动作监督；padding/history、失败和未知的动作 mask 沿用 P2R1。
7. 未来查询只保存在训练监督侧；政策输入只含指令、因果 RGB 和合法已执行动作。元数据、未来帧、事件真值、任务状态、场景 ID 和坐标都不得进入部署输入。

## 3. 保质的硬检查

- 来源：物理路径不越界；每个实际加载资产先核哈希；环境版本、配置、生成器代码和种子入账。
- 划分：先完成来源 train 房屋的旧暴露审计，再冻结本线 fit/dev/confirm 分组；当前清单全部标记 UNASSIGNED。无法确认未暴露的房屋不称 clean confirm。不得把官方 val/test 转成训练示范。
- 分组：同一房屋的所有路线、历史、续接、模板改写整体同组；组合泛化另留模板/组合，不靠随机分帧。
- 物理：动作合法、连续时间、碰撞与超限明确处理；不以 teleport 或拼图片替代真实历史。
- 标签：证据链、同实例连续帧、T/F/U、STOP 时序、任务检查器双重复算；无法自动认证的样本隔离，而不是等待人工逐例审核。
- 机制：检查同 task/query 的历史反转、无关绕行不变性、语言条件性、精确汇合和公共尾部。当前画面/步数/query 单独不能成为答案捷径。
- 输入：从白名单构建 policy records；读取 future query 不得改变已算出的 prefix memory。tensor/梯度级检查属于后续 G2，不以 JSON 检查替代。
- 审计：每个候选都进入 attempted/accepted/rejected/unknown 账本，失败类别、分房屋通过率和成本全量报告。
- 持久化：写临时 shard、关闭后复核再原子提交索引；崩溃后按 job ID 续跑，已封存产物不覆盖。

## 4. 保量的分批目标：不是已取得数量或自动扩容许可

| 分支 | 首批 | 小规模生产目标 | 后续扩大条件 |
|---|---|---|---|
| 普通导航 | 100 条不同参考路线，至少 5 个 fit 房屋 | 1,000 条不同路线，至少 20 个 fit 房屋 | pilot 通过后覆盖冻结 fit 子集内全部可用原始指令/路线；不能把留出的房屋也算训练量 |
| 机制数据 | 1 个完整认证族 | 30 个族、至少 5 房屋；再 300 个族、至少 20 房屋 | 跨房屋生成协议和快捷特征检查通过、实测产率可接受，再定千族级配额 |

首批数字是生产规划，未宣布规模可达；不能为凑配额丢弃难房屋后隐瞒筛选。
统计至少同时给出：独立房屋、物理路线、独立族、任务表达、有效 cell、监督决策、唯一 RGB 帧和重复率。
1 个 3×3×2 族的 18 个 cell，或 3 个种子的 54 次求值，不能算 54 个独立族。

磁盘与工时先从实际 pilot 估算：
`总字节 ≈ 去重帧数 × 实测平均帧字节 + 监督/索引字节`；
`墙钟 ≈ 待重放动作数 / 实测动作吞吐 + 规划与验证开销`。
未测动作长度与吞吐前不承诺一天生成全量，不用参考路点数量冒充帧数。
机制 mask 可优先存证据帧与可复算清单；正式存储方案需保证其完整性证书能够复核。
