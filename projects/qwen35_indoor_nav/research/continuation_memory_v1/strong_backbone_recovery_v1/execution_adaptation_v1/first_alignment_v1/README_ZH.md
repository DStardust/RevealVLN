# FIRST 训练对齐：直接优化模型

当前目标是扩大导航收益。旧 head 训练所有生成动作位置，部署 FIRST 却只在第一个位置施加残差；这一训练和执行位置不一致是本轮具体修改对象，不承诺它一定提高 SR。

本轮新训 CURRENT 和 DELTA，各种子 42/43/44、每模型 3000 步。使用同一批 270 条真实 FIT 轨迹、原保存初始化、原 schedule、原类别权重和损失系数。区别只在于动作损失选取 offset=0；每一个实际观测仍更新记忆，完整历史参与反向，未知前缀不变为负标签。原始数据的 training_admission 字段不覆盖。不是继续训练旧 FINAL，也没有改架构、增加参数、调 STOP 或使用 unseen 标签训练。

数据包含 142 条恢复和 128 条成功保护轨迹。FIRST 提供 1923 个已知恢复标签（含全部 142 个恢复 STOP）和 1999 个保护标签（含 26 个在 FIRST 位置的 STOP）；其他位置本来不施加残差，其标签不再训练该分支。失去的训练曝光如实计数，不能仅以同更新步数声称监督数量相同。

新轻量训练允许与已登记的旧评测共享 GPU，每个训练进程限制 2 GiB，不加载或更新底模。独立 pipeline 训练后会自行登记新模型并等待旧任务释放大模型评测资源，再在 GPU 0–7 运行。无需聊天会话在线。

固定原发现集全部 80 条 unseen，原生 + 旧 CURRENT/DELTA 三种子 FIRST + 新 CURRENT/DELTA 三种子 FIRST，共 13 臂、1040 次执行。每条路线在同一模型进程中重跑全部条件；不拿旧分数代替控制。主比较是同架构同种子的新训练−旧训练，同时报告原生、SR/SPL、救回/改错及动作成本。80 条已暴露，是开发改进实验，不是新盲测。训练共同修订的收益不能单独归为 DELTA 架构贡献。

入口：prepare.py --run runs/alignment_001；然后通过上层 standalone.py 提交 pipeline.py --run 同一绝对路径。恢复使用新服务名并加 --resume，模型与完整导航组按既有断点验收。实时网站新增 /api/first_alignment。CPU_TEST_RESULT.json 记录真实 FIT 特征测试；训练或 CPU 测试通过均不等于导航收益。
