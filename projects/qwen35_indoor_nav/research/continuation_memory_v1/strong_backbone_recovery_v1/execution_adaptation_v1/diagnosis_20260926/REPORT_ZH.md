## 已有证据支持什么

1. 两种写入方式都落后于同进程原生，因此不能把共同退化单独归为 DELTA 失效。DELTA−CURRENT 三种子成功数差为 −3/+3/−6，尚无稳定方向。各组干预前输入/动作审计通过；本快照六模型与 NATIVE 的审计均记录 logits 逐位相同。
2. 已经能救回部分路线，但改错更多，且平均动作明显增加。六个种子/方法组合合计 255 个退化记录中，204 个（80%）的首次生成差异位于第 2–4 个动作；153 个救回记录中也有 113 个（73.9%）首先在这些位置发生差异。这是定位线索，不是“删除后续干预就必然净获益”的反事实证明，亦不是 255 个独立路线。
3. 固定真实 DEV 恢复轨迹的 1,803 个已知标签上，原生正确 1,168 个（64.8%），新模型正确 1,330–1,392 个（73.8%–77.2%）。相同教师执行轨迹上的动作预测改善，并未转化成自主闭环收益。后续自主产生的动作前缀不同，不能将教师强制缓存上的准确率当 SR。
4. 正常 DEV 轨迹 1,686 个标签上，原生正确 1,682 个；每个新模型额外改错 17–22 个原本正确的动作。长轨迹连续执行会放大少量单步改错的影响，但本轮没有独立量化这种放大的因果比例。
5. 运行记忆并非完全不起作用：在 DEV 恢复缓存中清零记忆会改变 26–65/1,803 个动作。只是它的差异目前未带来稳定闭环增量。清零属于离线只读诊断，不是新导航成绩，也不能单独证明记忆语义正确。

## 尚未证明的原因

新模型在不少输入上抬高 STOP 相对分数，但同时存在漏停、进入范围后又离开，以及更长的轨迹。不能只凭偏置均值就将全部失败归因于“太早 STOP”。四类 argmax 与完整词表实际生成也需区分。

记忆写入存在较多 tanh 饱和，DELTA 的变化分支强度分布偏斜；这些是次级优化线索。本轮不据此直接换架构、改归一化或追加训练，以免多个变量混在一起。

## 一项有界调整

`../scope_validation_v1/` 只改变冻结残差生效的位置：ALL 对每次生成的最多四个动作生效；FIRST 仅对首动作生效，随后在下一次真实观测对应的生成起点重新允许纠偏。两者继续对每个实际观测更新相同记忆，STOP/动作预算/底模/权重/词表生成保持不变。

注册 80 条按房屋分层并按 ID 哈希确定顺序的已暴露 unseen，三种子、CURRENT/DELTA、ALL/FIRST，加同进程 NATIVE，共 1,040 次执行。重新执行 ALL 对照，不拼接旧轨迹。0 新训练更新；原 369 条评测结束后自动接续。完整组审计失败则停止，分数低不重试。

如果 FIRST 明显减少改错、保留救回并改善 SR，支持“扩大连续动作干预范围是共同退化因素”的工程解释；它不自动成为新架构创新。若仍退化，则不继续围绕该范围调阈值，应回到有正向证据的旧 CONCAT，再单独定位动作读出/训练分布。不得预先把这次调整写成成功。

原始证据：`SEALED_GROUP_SNAPSHOT.json`、`TRAJECTORY_DIAGNOSIS.json`、`HEAD_DIAGNOSIS.json` 与可执行 `diagnose.py`。诊断 0 GPU、0 优化器更新；完整 DEV 64 条以及按 ID 顺序每八条抽一条的 FIT 34 条用于冻结头的特征尺度检查，未用于调参或训练。
