# 执行结果校正导航状态：有界先例核查与候选增量

核查日期：2026-09-26。状态：DESIGN_HYPOTHESIS，非实验成果。本文件是整体 VLN 方案的版本化补充，不修改旧 FROZEN_SPEC、当前冻结模型或正在进行的扩大评测。此次没有安装环境、加载模型、运行 GPU 或复现下列方法。

一句话主问题：**机器人能否根据动作真正带来的观察变化，持续校正自己已经完成什么、接下来该做什么，并把这种能力迁移到新环境？**

整篇工作的目标可以覆盖普通 VLN 和室内外迁移；当前 StreamVLN 小幅收益只是其中一个状态模块的起步证据。它尚未证明长历史必要，也没有室外迁移证据。

## 可实施的候选：用执行证据更新，而不是把动作意图当完成事实

候选差异应落在一个具体、可否定的学习问题上：同一指令下，模型发出了相似动作，当前视角也可能接近，但实际执行经历使任务状态不同；训练部署时使用的状态更新器区分这些情况，并验证这一区分确实改变了正确动作与合法终止。这里的差异是待检验设计，不是已确认的独有贡献。

| 层面 | 可以实现的增量 | 最强简单对照/何时撤回增量 |
|---|---|---|
| 数据 | 真实前缀、实际执行动作、执行后观察、可核验状态变化成组保存；覆盖有效移动、错误转向、未达到预期的执行、回返与恢复。每个事件保留证据、UNKNOWN 和完整候选漏斗；同源路线与表达族隔离 | 给所有方法同一动作轨迹池。若普通 BC 获取同等收益，不能把效果归给结果监督；不同当前观察可直接分辨的样本不能宣称“必须记历史” |
| 模型 | 当前局部特征与有限任务状态分开；在新观察到达后，利用前一实际动作及前后观察变化校正状态。先保持小模块，与当前冻结基座对接，不加在线规划器 | 同容量最近 8 步、等幅度 EMA、普通 GRU/固定写入率，以及移除执行结果的同架构。只有超过这些对照，才谈选择性状态更新的价值；归一化/门控本身不构成创新 |
| 训练 | 动作监督＋已核验状态转换监督，并保留普通成功轨迹上的动作/KL约束。实际未来观察在时刻 t 只能作为训练目标，在 t+1 到达后才能进入运行状态 | 精确组合式状态监督、普通动作条件下一特征预测、逆向动作预测，以及相同数据/更新预算的混合单阶段训练。若精确状态或普通 dynamics 已同样有效，应采用更简单方案 |

三者可以组织为同一篇工作：提供能检验执行与意图不一致的数据，学习会用新证据校正的状态，设计在正常导航与偏离执行上共同训练的方式。不能因为希望拥有三类贡献而预先将三个模块都判定为贡献。

运行逻辑只需要：先用因果历史产生动作；动作真正执行并收到新观察后，再更新状态。预测误差可以作为一个可学习证据，但“预测误差大＝任务没完成”不是可靠标签：相机转动、光照变化也会造成视觉差异。目标距离、碰撞真值、未来观测、检查器状态不得直接输入动作头；训练标签可用审核真值，但必须注明可观察性和未知掩码。

为了面向室内外，状态语义应优先描述“是否通过指定地标、转向是否完成、是否仍需继续、是否有足够终止证据”等指令关系，避免把若干室内房间类别写死成全方法。已有 R2R 最短路教师标签不自动提供这些语言事件真值，现有动作数据不足以凭空产生完整任务状态标签。

## 当前等待期的合理顺序

1. 对已有 FIT/DEV 因果缓存检查前后观察、实际动作及标签是否可对齐；只读分析最近窗口、等范数历史与简单时间平滑。现有“完整历史不优于最近 8 步”的结果应保留，先定位再决定是否需要更复杂记忆。
2. 做独立 CPU 原型与信息泄漏/梯度测试：固定同一 actor 输入，只改变合法历史；终点监督必须能影响实际运行状态写入。此步只验实现，不报告新导航收益。
3. 冻结一个小规模比较：BC、精确状态、普通 dynamics、候选执行证据校正；共享轨迹池、初始化和成本。现有正在运行的 unseen 扩大验证维持不变，不按其路线逐条补训练。
4. 室内外迁移要单列：先室内训练后冻结状态模块，在未参与选择的室外任务上验证；若使用室外适配数据，明确改称少样本适配。不能把改动作接口、换低层控制器或增训练数据的共同收益归给状态模块。室外资产/模拟器可用性本轮未审计，不把此计划写成已可启动运行器。

不应声称的三种宽泛创新：**首次把记忆用于导航；首次通过动作结果或未来预测训练导航；首次以两阶段和室内外混合数据训练通用导航。** 应争取的是具体的数据关系、状态更新机制及匹配控制下的跨域实证，而不是重新命名这些已有组件。

## 补查：同前缀、候选短动作、统一续接控制器的结果监督

本节仅增加两个一手方法来源，仍不启动任何运行。

| 来源与读取范围 | 与候选设计的直接重叠 | 应如何使用 |
|---|---|---|
| [LOLS，ICML 2015](https://proceedings.mlr.press/v37/changb15.pdf)，实际读取 Algorithm 1、式(2)和关于 roll-out 控制器的段落 | 从 roll-in 到达的同一状态，对候选动作进行 roll-out，以最终代价形成 cost-sensitive 标签再训练策略。“同前缀＋动作分支＋续接结果”在监督算子层面已被覆盖 | 固定短动作块、真实仿真以及统一后续控制器是具体实现与实验控制，不自动变成新训练范式。固定控制器得到的是相对于该控制器的代价，不能称全局最优动作，也不能直接继承 LOLS 的理论保证 |
| [AeroDPO，v1](https://arxiv.org/html/2608.07557v1)，实际读取回滚、特权纠偏、偏好筛选与 DPO 方法段；[作者仓库](https://github.com/XuPeng23/AeroDPO)只读入口 | 室外 UAV-VLN 已从实际碰撞前的状态回滚，构造 rejected 动作，借助离线几何纠偏与视觉筛选获得 chosen 动作，再做 DPO | “环境反馈＋偏好对＋离线后训练＋部署无教师”已有直接导航先例。我们可要求所有分支均有真实完整执行证书，且监督完整任务结果而非只避碰；但不能仅凭这一区别宣称新算法 |

拟议数据可写成 `C(h, a; pi_follow)`：真实历史 `h` 结束后执行预注册短动作 `a`，随后由冻结的 `pi_follow` 继续，记录主动 STOP、全预算成功、成本及 UNKNOWN。所有候选从经核验的同一前缀状态开始；在离线采集时可恢复有证书的快照，但不能在自主评测中途传送。需登记物理状态、剩余预算、随机性、控制器权重及其历史缓存，不能只固定网络参数就说后续控制条件一致。

**这种分支结果本身首先是动作代价监督，不是历史必要性的证据。** 同一个前缀的分支只能说明动作不同会怎样；要验证任务状态表征，另需近似当前窗口却有不同有效历史的真实配对。对于成功仅取决于终点的普通导航，若物理状态、目标和后续控制器状态都相同，相同续接可能根本没有历史相关标签差异。若保留不同控制器历史缓存导致结果不同，则标签也反映了该控制器的记忆行为，不能冒称纯粹的物理任务真值。

可讲清的候选增量是：**利用成组、真实执行的分支结果来训练部署时的有限任务状态，使它保留能改变后续动作价值的历史信息，并检验这种表征能否跨环境迁移。** 这是待检验的表征学习与数据设计主张，不是发明 rollout-cost 或 DPO。单纯将同一 cost 向量多接一个 reader、换成 BCE/排名损失，也不足以成立独立算法贡献。

最重要的匹配对照：

1. 同轨迹池只做动作 BC。
2. **同一递归架构、同因果输入、同初始化、同分支结果**，直接做 cost-sensitive 动作学习或 DPO；不把它故意削弱为无记忆策略。
3. 同一架构做精确状态监督与普通动作条件未来预测。
4. 候选在上述共同底座上增加登记的任务状态关系监督，匹配标签曝光、更新和计算；只有其独立增量超过(2)/(3)，才能归因于状态学习。否则采用直接代价/偏好学习，不能靠“执行结果”名称维持创新。

未来部署仍为因果状态更新和直接动作选择，不要求在线搜索、真实分支试走或在线 RL。室内外迁移目标保持，但需要独立域证据；本节的文献与设计分析没有产生任何新的导航结果。
