# 真实历史机制补样本

本目录新增数据构造，不修改 V16 的旧模型、数据、标签或结果。目标为原有四个 FIT 屋、一个 DEV 屋各八族，共 40 族；这是机制开发规模，不是论文统计充分性保证。正式 TEST 不访问，不启动训练。

每族从同一个位置和初始朝向真实执行四段历史：有见证、无见证，以及分别保持同一状态的不同历史。四段长度和左右转计数相同，末两张原始 RGB、语义、位姿、最近八动作严格一致。所有轨迹均无中途设置状态、无碰撞，原始数组保存。历史见证必须离开最近窗口。

每段历史完整执行立即 STOP、重新获取锚点后 STOP、错误终点 STOP 三个后缀，共 12 次物理执行。原 SEE2/256 像素/同实例连续两帧语义保持不变。每次对任务 A 和不要求锚点的 task_T 分别求值，共 24 个标签。标签数不冒充物理轨迹数。

这里构造的是**原地转向观察与历史条件终止**；不是跨房间导航恢复，也不是对原 V16 双锚点任务的直接替换。验证通过也不自动意味着普通 VLN-CE SR 提升。

先导：`probe_001` 的简单转出返回未能得到精确汇合，保留失败；`balanced_probe_001` 完成 924 个等计数动作序列，得到精确汇合动作组，仅作提案来源，不计合格族。

`collect_001` 在两屋认证 16 族后因第三屋 reserved semantic mask 签名冲突停止。`collect_r2.py` 按旧采集器已有的完整语义签名排除规则修复，`REUSE_001.json` 保留来源及哈希，`collect_002` 继续剩余屋；不改变已完成族的物理与标签语义。新任务停止后 `finish.py` 自动运行原始数组复核和导出。

查看独立服务进度：

```bash
cat runs/collect_002/STATUS.json
tail -n 30 standalone_jobs/ident-collect-20260921-02/job.log
systemctl status q35n-ident-collect-20260921-02.service
```

`review.py` 从原数组重新计算像素计数，重算全部标签/当前输入/跨分割一致性，导出 `POLICY_INPUTS.json`、`SUPERVISION.json`、`FAMILIES.json`、`CONTENT_MANIFEST.json`。策略文件仅提供指令、RGB 引用和已执行动作；状态、查询、标签与元数据仅用于离线监督和审计。

`SHORTCUT_AUDIT.json` 单列动作序列与历史状态的关联。精确当前输入对照不自动排除整个历史动作模式的捷径；这批数据需搭配动作历史单独输入、短窗输入和正常模型的对照。重复查询/帧/同屋族之间相关，不按独立样本统计显著性。

CPU 验证命令：`python3 -B -m unittest -v test_certify`。七个反例/正例测试检查缺单元、碰撞、位姿差异、传送、STOP 凑帧和假负例拒绝。测试样本为合成契约数据，与真实采集数量严格分开。
