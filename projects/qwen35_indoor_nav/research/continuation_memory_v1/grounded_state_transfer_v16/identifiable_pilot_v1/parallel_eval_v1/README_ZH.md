# 六卡评测接续

用户于 2026-09-21 明确授权使用 GPU 2–7，并要求用完恢复占位。`AMENDMENT.json` 将单卡执行改为完整条件分片，原模型、数据、动作选择、成功定义和 576 次计划分母不变。

独立服务：`q35n-ident-parallel-20260921-01.service`。
统一监控：<http://127.0.0.1:18770>（沿用原 SSH 端口转发）。

## 当前入口

- `STATUS.json`：六张卡状态、各自模型/条件/决策、总 GPU 会话小时、最终停止原因。
- `PLAN.json`：原单卡已完成组和六个无重叠分片；按剩余 condition ID 排序轮转分配。
- `gpu_2` 至 `gpu_7`：配置、进度、标准输出、进程身份、退出记录。
- 原 `runs/pilot_001/evaluate/session_*`：保留旧结果，新增每卡独立 session，九模型完整组封存后才计入。
- `HANDOFF.json`：核实的原服务身份与停止记录。可能已开始的下一组保留为未封存尝试，没有接续单臂或按低分重跑。

## 资源和恢复

占位进程已核实来自原 `gpu-placeholder.service`，物理范围为 2–7。使用它的原有 `acquire/release` PID 租约；不手工删除、修改或批量杀占位脚本，不影响其他进程。协调进程异常退出后原守护进程也会清理失效 PID 租约。

原守护进程管理整套六卡：全部评测 GPU 进程退出、租约释放且满足原空闲等待时间后，统一恢复占位。`PLACEHOLDER_RESTORATION.json` 记录实际恢复是否得到确认；如有其他任务使用这些卡，不会强制抢占它们。不会声称服务存在就等于显存已重新占满。

总 GPU 会话小时仍受原 8 小时上限约束，六卡时间相加；旧单卡中断段使用保守墙钟估计并明确登记。训练没有增加更新，完整低分条件不会重跑。正确性失败会保留已封存组，清理自身进程并释放租约。

全部完成后自动运行冻结 CPU review，并输出 `DEVICE_BLOCKS.json`，区分原 GPU1 组和新 2–7 卡组。原 `PROTOCOL.json`、来源锁和所有已训练模型不改写；新运行条件由本目录修订及每个 session 身份说明。
