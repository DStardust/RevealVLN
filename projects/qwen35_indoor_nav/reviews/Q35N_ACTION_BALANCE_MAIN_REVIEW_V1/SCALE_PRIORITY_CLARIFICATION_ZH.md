# 用户反馈后的规模裁决：小集诊断不能替代正式导航 SFT

用户指出从VLM建立VLN时，当前训练步与数据规模不足。主agent接收这一范围纠正，不把小集FAIL推成方向失败。

## 三种数量必须分开

| 层级 | 实有规模 | 能说明什么 |
|---|---|---|
| 原始合法来源 | R2R-CE v1-3 train：3,603物理参考路线、10,819指令任务、61房屋 | 已有路线/指令与场景资产；不等于已生成RGB/动作 |
| 已验收普通pilot | 99路线、298指令、5房屋；其中SFT划分75 train路线/226指令/12,276决策，24条route-dev仍在同5房屋 | 工程pilot，场景与任务多样性不足以支持通用VLN |
| 最近两次匹配小试 | 每次10路线/565唯一决策，200更新/6,277训练决策/1,228,519 token | 约11.1次决策等价重复，单次温和加权对照，不是正式基座训练 |

因此，200更新既不能说“足够训练Qwen导航”，也不能只按更新数说“完全没重复学习”：它重复了小集约11遍，但只覆盖10路线。
先前完整75路线SFT也仅约一遍数据，不能代表充分训练。
Qwen来自通用VLM预训练，不是从随机权重训练，但导航输出/执行记忆仍需足量任务适配。

## 正式调整后的推进顺序

1. **数据扩量准备与短接口归因并行安排，不再串行等待10路线达到95%才允许准备数据。**
   自动回放、质量检查和分组规则沿用已通过普通pilot；不另起人工标注工程，不等机制族通过才扩普通数据。
2. CPU先冻结房屋分组和路线配额，下一普通生产目标沿用既有管线的1,000条独立路线、至少20个训练房屋，配套独立房屋dev/confirm；保留原始指令。
   使用全部合格原指令，但不得把同路线的三种措辞报成三条独立路线。官方val/test不进训练。
   分批提交不可变shard，先100–200条新增路线检查吞吐/跨房屋通过率，再按既定配额推进；保留全部失败和拒收原因。
3. 工程接口诊断限定为短任务：排除标签错位、输入不起作用、梯度被异常模块支配等具体错误。
   10路线未达到95%不是“增加更多数据必然无效”的定理；也不能用更多数据掩盖已确证接口错误。
4. 正式训练按epoch、有效动作决策数和token总量规划，不沿用200步作为基座终点。
   建议先将已有完整75路线训练池作为学习曲线中间档，再到1,000路线；每档预先固定训练预算与独立dev检查点。
   比较1/3/5遍等预算曲线是规划候选，尚未冻结或执行；不能中途看到某个点好才改主终点。
5. **加速是扩量前的必要工程工作。** 当前两卡仅3.458决策/秒；12,276决策一遍约59分钟，五遍约4.9小时，均为按小集吞吐线性外推、未实测全池。
   千路线一遍可能需十余小时，需用实际长度重新估算；未验收官方训练内核/批处理/四卡前，不宣称今天可跑完大规模SFT。
   下一效率工作优先官方线性注意力训练内核与真实四卡吞吐，不采用已数值失败的三角重写。
6. 足量普通VLN先形成可运行与可评估的底座，再加入已预审的交叉续接监督，并与同数据、同计算的普通SFT比较。普通数据扩量本身不冒充论文算法创新。

本文件是对范围与优先级的纠正；没有启动新数据生产、安装、GPU实验或长训。
本轮权重修复的失败不改写，后续执行仍需具体的数据/效率/训练协议，而不是再次泛搜文献。
