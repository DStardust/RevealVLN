# 主 agent 提前停止：构造约束诊断，不是256耗尽结论

运行过程中静态复核发现 frozen engine.candidate_base 对 L loop 使用 forbidden=[D,K,B]；但 MINIMAL_FAMILY_SPEC_V2 的 H_D_L 只要求已经发生 D、随后发生 L、没有 K。D 在已完成 D 的无关绕行中再次出现不改变任一任务的结果。额外禁止 D 是搜索启发式的过强条件，不是任务/证书所需条件。

当前 coverage-only 节点继续遍历相同过强构造器不能解决此问题。主 agent 依据本轮补齐机制族授权提前停止自己启动的 worker，由原 runner finally 恢复占位。实际已完成候选数以停止后的账本为准，不能宣称256全部失败，也不修改旧失败节点。停止中的一个候选可能只有子路径日志，没有完成的 family rejection；需单列 interrupted in-flight。

下一独立版本优先检查合法原地转向形成不同可见历史，再用真实平移续接完成导航：无需逆向平移，不改变运动原语，不要求每个历史必须走远。保留原两任务/3历史/3续接、等长/public tail、精确像素汇合、1e-4 pose、512/160和零碰撞标准。该接口构造若可行仍不是自然导航性能证据。
