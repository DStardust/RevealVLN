# 普通导航基座训练准备 V2

2026-09-10。用户本轮要求先准备用普通数据训练一个基本导航模型。
本目录负责新训练数据接口、完整轮次训练候选和验收准备；不改变
MAINLINE_FREEZE_V3，不修改七条生产队列、旧训练文件或冻结输入锁。

## 目标与本轮边界

第一目标是 Qwen3.5-2B 能根据自然路线指令在闭环环境中运动、转向、到达并停止。
当前只训练准备普通动作监督，特殊交叉续接、reader、强 M2 等均不进入这版训练。
这不是新的论文机制实验，也不把普通数据扩量当作算法创新。

过去最近两次真实更新只有十条路线、565 个独特决策，重复训练不能补充场景覆盖。
这不足以判断正式基座训练是否可行；同时 STOP 为零和梯度波动原因仍未全部定位。
数据规模不足不是唯一已证实原因，不能承诺扩量必然修复优化或接口问题。

本轮 CPU 准备不停止生产、不借卡、不加载模型权重、不执行参数更新。
GPU 训练须在生产自然释放资源后核验实际身份、通过新接口及吞吐验收，
将具体设备、时间、存储和 token 预算绑定新 RUN_ADMISSION。旧授权不自动转移。
本目录候选 runner 的单 GPU 前向不代表正式多卡实现，也没有已测提速。

## 数据快照与完整性

首版使用交接八个已经闭合并严格审核的普通池：R2R 和英语 RxR 的官方人工指令。
生产口径期望合计 5,849 物理路线、17,548 条指令、1,394,744 条指令条件动作。
最终以 snapshot_v1/RESULT.json 的实际去重、元数据核对结果为准。
不纳入旧 99 路线 pilot、失败/partial/隔离项、特殊族或活动中的 EnvDrop 分片。
EnvDrop 待整 lane 最终合并后进入独立后继快照，并单列合成指令采样与收益。

prepare.py 对闭合凭据、原索引哈希及计数、隔离名单、房屋划分、policy/supervision
元数据、动作对齐、末尾唯一 STOP 进行核对，保存源文件哈希及新快照封存。
索引只读引用原图像，不复制 content、不覆盖旧 training_admission 字段。
本轮不重新回放仿真或全量解码 RGB；训练读取每幅图时校验解码像素哈希。
源 JSON 和索引一致性不等同新的物理/自由自然语言语义认证。

计数分别报告物理路线、物理动作、原指令和指令条件动作。相同来源、指令、
真实 RGB/动作序列的重复行只保留一次；同路线不同指令不算新物理路线。
训练 manifest 的 ID/路径/hash/scene/目标位姿等只供读取、审计和分组，不能进入模型。

## 数据到动作模型

每个原指令记录从零记忆开始，按真实时间顺序读取；每步只允许指令、最近两张
224×224 RGB、最近八个实际已执行动作、上一时刻八个连续记忆槽。
三种运动类统一为 move_forward/turn_left/turn_right，终止类统一为 STOP。
行为尺度保持前进 0.25m、转向 15°，90° HFOV，传感器高 1.25m，RGB-only。
数据 loader 控制字段与策略白名单分离，监督 actions[t] 不出现在该步 executed_actions。
晚期单步不能从零记忆冒充完整历史；换指令必须 reset，跨路线不传记忆。
STOP 保留为真实末尾监督，资源超时、碰撞拒收和缺帧不能补为 STOP。

模型沿 Qwen/Qwen3.5-2B revision 15852e8c16360a2fea060d615a32b45270f8a8fc；
冻结视觉/基础权重，rank8 LoRA q_proj/v_proj、8×2048记忆槽、writer及四类动作头。
从通用预训练权重和固定 seed 的新导航参数初始化，不从历史失败终态继续。
保持官方 MRoPE 和现有原生算子；不采用已失败的三角重写。
不使用完整跨步 KV cache，不添加未来 query、事件真值或额外语义传感器。

## 普通动作训练候选

预定三遍完整指令池，按 seed=1109 的逐 epoch 全量打乱顺序访问，每条指令每遍一次。
保存第1、2、3遍边界 checkpoint；第一遍是完整规模检查点，不是200次更新即收口。
首版使用未加权四类动作 CE，按累计有效决策数归一，末段和 STOP 不丢弃。
已有轻加权实验未被采用为有效修复，不照抄其收益叙事。

普通 CE 的参考实现保留每4步截断反传、8段累计再更新；路线上持续传递记忆值。
它只定义普通动作基线，不证明百步历史末端监督已训练早期记忆写入。
TBPTT 对后续机制 BCE 是否成立需独立验收，不能把本版直接当特殊训练器。
优化候选 AdamW lr=1e-4、weight_decay=.01、gradient_clip=1，常数学习率。
这些是待真实接口/吞吐验收的固定参考配置，不称最佳超参数或已解决 STOP 问题。
任何替换优化器、批处理公式或记忆回写尺度的修订独立版本化，保留原失败。

token_audit.py 用本地 processor 在 CPU 测完整指令池的短窗 token 上界，
核对最长样例的实际图像展开长度，并分来源/房屋实读首尾 RGB。
旧512-token上限不得通过静默截断指令解决；新上限由审计和未来GPU显存实测决定。

## 评估来源和成功含义

完整沿用 ordinary_scale_v1/SPLIT_FREEZE.json 的51 FIT屋、5 INTERNAL_DEV屋、
5 INTERNAL_CONFIRM屋。所有原始家屋及关联轨迹/指令/变体在同一组。
预留房屋可能有旧线暴露，不声称基础模型或项目历史从未见过。

本轮仅从原官方 train 的 SOURCE_MANIFEST 元数据中，在每个 INTERNAL_DEV 屋
为每个来源固定选择至多10条不同物理路线，最多100条路线，每条选定一个原指令ID。
来源不足的分层保留全部可用来源并明确报告缺额，不跨屋/换来源补足名义100条。
先按物理路线哈希固定排序、再按记录的确定规则选择措辞，选择与模型结果无关。
DEV_SOURCE_INDEX 是评估来源，不是已生成RGB、可训练样本或已运行episode。
不读取官方val/test答案，不把开发/确认房屋用于补训练数量，不打开confirm结果调参。

后续闭环在固定相同episode上评估初始化和各epoch checkpoint，记录 SR/SPL、
nDTW/SDTW、到达但不停、过早停止、碰撞、预算耗尽与服务错误，按来源/房屋分报。
成功半径和路线指标沿已登记基准定义；不能用目标最短路或位姿指导策略动作。
训练/离线诊断记录四类混淆矩阵、每类recall/precision、STOP TP/FP/FN、CE、
长度分层和逐屋结果；总体accuracy不作为“基本导航已成功”的唯一依据。

GPU运行前另冻结闭环资源预算与数值验收阈值。当前未测模型结果用 null，
不把CPU测试、teacher-forcing精度或训练集小集过拟合称为闭环导航通过。

## 吞吐与执行顺序

旧双卡实测3.458决策/秒只用于成本外推；139万动作一遍约4.67天，三遍约14天，
300万动作一遍约10天，不含新增评估/重算成本，不代表本版实测吞吐。
正式训练需要真实批处理、多卡数值正确性与吞吐验收；本轮不承诺线性多卡加速。
候选 runner 仅提供可审计参考执行，不作为生产规模效率已通过的证据。

先完成 CPU 数据快照/adapter/调度拒绝路径 → 空闲资源上的真实短接口、
标签错位与输入响应、STOP/梯度、重载及吞吐验收 → 冻结实际多卡和时间预算 →
普通完整轮次训练与独立房屋闭环。短诊断不再以十路线95%作为扩量准备前置条件。
七条生产队列全程保留；占位只能在最新精确身份核实后按新预算借用并恢复。

本目录没有自动后台等待启动器，不会因训练命令文件存在而占卡或开始训练。
