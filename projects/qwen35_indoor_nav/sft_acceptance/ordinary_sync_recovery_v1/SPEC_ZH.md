# 普通导航基座：多卡停滞修复与受控续训 V1

授权：用户 2026-09-11 明确要求“修复目前的问题然后继续训练”。本节点只修复普通基座的运行可靠性，不开展新方法实验或特殊数据融合。

## 不变量与修改范围

- 原 ordinary_baseline_v3 源码、协议、输入锁、检查点与历史失败只读保留；新实现和新输出只写本目录。
- 保持 Qwen3.5-2B、LoRA、四类动作头、普通 FIT 数据及因果输入白名单、batch 计划、inflection 权重 3.2、AdamW 与原余弦学习率计划。
- 唯一允许使用原训练 GPU 3/4/5；旧自动重启器先停止，再通过原租约收尾回收卡并恢复占位。新租约重新核验原占位的实时身份、仅精确释放，并在退出时恢复。不得停止其他训练、采集或 GPU 6/7 占位。
- 修复按本地墙钟触发日志导致的 collective 次序分叉；所有 rank 在固定训练步和共同停止边界执行一致通信。进程组使用有限超时。模型初始化绑定当前 rank 的设备，避免每个 rank 先在 cuda:0 建额外副本；不改变模型参数定义。
- 续训读取最新 hash/receipt 校验通过的完整检查点，保留优化器和 LR 游标；明确记录未保存更新的回退和重放成本，不宣称跨 FLA 内核逐位一致。
- 修正跨恢复吞吐与 rank 本地决策计数账目；旧日志保留，无法观测的尾部成本标为未知。新预算不超过旧 60,000 更新 / 4,500,000 决策上限，历史已观测计算和经过墙钟不清零。
- 只读监控提供新运行的心跳、日志年龄、步数、检查点、预算与训练窗口指标；训练准确率/STOP 召回不等于闭环导航成功率。

## 验收和停止条件

1. CPU 测试及真实三进程 Gloo 测试覆盖时钟偏差、仅一个 rank 收到停止、epoch 边界、预算以及恢复账目。核验原输入/代码绑定。
2. 停旧进程前留存 PID/starttime/父子关系、GPU、最后进度与检查点凭据；只对复核一致的旧重启器和旧训练子进程发信号。不得修改失败为 PASS。
3. 新 GPU 运行需恢复到指定游标、连续推进超过旧 30,499 步、日志多次更新，并产生至少一个重新校验成功的检查点，才可报告恢复成功。
4. 单生产者锁；有限次数恢复；启动/无进度超时都记失败、清理自身子树。超出预算或重复无进展后退出，恢复占位，不无限重启。
5. 本次只判运行修复；模型收益、DEV 和真实导航 bench 均未验证。
